# Quickstart: Generation Execution and QA

1. Start PostgreSQL and apply the 011 additive migration to an isolated database.
2. Generate a compatible approved four-second portrait GenerationPlan plus incompatible duration,
   aspect, missing-slot, ambiguity, and tampered-file fixtures.
3. Preview selected shots twice and prove identical hashes, blockers, five slots, prompt facts,
   workflow identity, separate call caps, and zero writes/external calls.
4. Confirm a Fake four-shot subset; run the Worker sequentially and verify one target/job/submission
   record per shot and a `0 / 0 / 0` external call ledger.
5. Inspect each retained fixture video, technical facts, FIRST/MIDDLE/FINAL frames, Fake advisory QA,
   and blank Human QA.
6. Record PASS on one Artifact and FAIL on another; reload and prove append-only history plus future
   assembly eligibility only for PASS.
7. Exercise technical failure pause, expired authorization, duplicate confirmation, cancellation,
   ambiguous reconciliation, and a new linked attempt requiring new Preview/authorization.
8. Run unit, contract, default, and sequential isolated PostgreSQL suites; rehearse migration against
   preserved Phase 0-4 data; then run type, lint, format, build, secret scan, and diff checks.
9. Run browser QA against isolated data for selection, blockers, confirmation, progress, playback,
   review frames, AI findings, evidence disclosure, and Human QA controls.
10. Stop before LIVE. Re-check current H3 price/credential/Credits and exact one-shot Preview. Present
    one combined maximum `1 H3 + 1 conditional CodexManager QA` scope and obtain fresh owner
    confirmation before any external call.

Automated acceptance never sets LIVE environment gates and must end with Generation Provider 0,
ComfyUI 0, CodexManager 0, and video generation 0.
